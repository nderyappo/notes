Ивар:
представляю себе 2 варианта

первый:
1. сервис интеграции получает список марок/моделей от СК
2. по запросу из ядра отправляет его для установки соответствия с нашими данными
3. получает запрос со связками наши-их данные
4. сохраняет связки в своей БД и пользуется

второй:
1. сервис интеграции получает список марок/моделей от СК
2. запросом к ядру получает список наших марок/моделей
3. ищет соответствия, найденные сохраняет в БД
4. не найденные отправляет в ядро для уточнения
5. получает запрос из ядра с уточненными связками
6. сохраняет связки в своей БД и пользуется

для поиска соответствий можно задействовать ИИ, например, ГигаЧат
чтобы минимизировать обращения к ИИ, можно для этого сделать отдельный сервис, который будет заниматься сопоставлением с нашими данными данных всех интеграций

после первой итерации сопоставления делаются только по изменениям в наших данных и данных СК

это вкратце, готов обсудить детали
-----------------------------------------------------------
по поводу маппинга моделей
я думаю, у всех интеграционных микросервисов нужно добавить 2 эндпойнта в провайдер:
1. получение списка марок/моделей с привязкой к нашим моделям/модификациям
2. установка привязки
первый мог бы возвращать массив объектов наподобие
{
  название_марки,
  модели:
  {
    ид_модели_у_СК (строка),
    название_модели_у_СК,
    ид_модели_наш,
    ид_модификации_наш
  }
}
второй принимать массив объектов вида
{
  ид_модели_у_СК,
  ид_модели_наш,
  ид_модификации_наш
}
пока у СК не попадалось явного разделения моделей на модификации, но, возможно, это заложено в модель, поэтому модель СК должна привязываться к нашим модели и модификации одновременно
если модификация не указана, то это мап для всех модификаций модели
пока не вижу смысла в удалении привязок, тут можно подумать
если использовать для поиска соответствий отдельный сервис, то он и будет делать эти вызовы
сам поиск можно сделать поэтапно:
1. точный поиск по названию
2. остальные по полнотекстовому поиску
3. остальные вручную (это можно совместить с проверкой результата пользователем в интерфейсе)
на любом этапе можно задействовать ИИ
сервис интеграции раз в сутки обновляет списки марок/моделей, добавляет новые без привязки, если находит существующую привязку с измененными данными, то сбрасывает привязку
хорошо бы уведомлять о таких изменения сервис поиска соответствий
